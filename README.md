# Olymp Helper — База законів і помічник фракцій

Десктопний лаунчер і внутрішньоігровий оверлей для гравців державних фракцій (GTA V / RAGE / MTA).
Мова інтерфейсу — українська. Побудовано на **Tauri 2** (Rust + WebView2), без Python і без серверної частини.

## Можливості

- **Лаунчер:** новини, кнопки ресурсів (Discord, форум, сайт, таблиці), банер проєкту, налаштування.
- **Оверлей:** окреме прозоре вікно поверх гри, що відкривається й ховається глобальною гарячою клавішею.
- **База законів:** живий пошук за статтею, назвою, описом і тегами (`Ctrl + K`).
- **Калькулятор покарань:** обираєте кілька статей і одразу бачите загальний штраф, час у КПЗ та рівень розшуку (до 5 ★).
- **Синхронізація:** база завантажується з GitHub під час запуску, кнопка «↻ Оновити базу», офлайн-режим із кешу.
- **Відстеження гри:** лаунчер кожні 3 секунди перевіряє, чи запущений процес гри, і показує статус.
- **Налаштування:** шлях до `.exe` гри, гаряча клавіша, прозорість оверлею, розмір шрифту, автозапуск з Windows.

## Вимоги для збірки (Windows 10/11)

1. [Node.js 18+](https://nodejs.org)
2. [Rust](https://rustup.rs) (stable, MSVC)
3. **Visual Studio Build Tools** з компонентом «Desktop development with C++»
4. WebView2 Runtime (на Windows 11 уже встановлений)

## Запуск і збірка

```bash
npm install
npm run dev        # запуск для розробки (без обфускації)
npm run build      # готовий інсталятор: src-tauri/target/release/bundle/nsis/*.exe
```

Першу збірку Rust компілює кілька хвилин, наступні швидші.

## Налаштування адміністрацією

У збірку вшита лише адреса **маніфесту**. Відкрийте `src/config.js` і замініть адреси (вони вказують на ваш репозиторій із законами):

```js
const MANIFEST_URL    = "https://raw.githubusercontent.com/your-org/gov-laws/main/manifest.json";
const DEFAULT_LAWS_URL = "https://raw.githubusercontent.com/your-org/gov-laws/main/laws.json";
```

Далі все керується файлами в GitHub-репозиторії **без перевипуску лаунчера**. Приклади лежать у `docs/examples/`:

| Файл | Що змінює |
|---|---|
| `manifest.json` | адреса `laws.json` і `news.json`, кнопки ресурсів, банер |
| `laws.json` | категорії та статті (структура з прикладу) |
| `news.json` | стрічка новин (останні 10 записів) |

Поля статті: `id`, `number`, `title`, `description`, `fine`, `jail_minutes`, `wanted_level` (0–5), `bail`, `tags`.
- `bail`: ціна застави числом, наприклад `8000`. Якщо застави немає, пишіть `null`. Для статей без КПЗ (`jail_minutes: 0`) поле не враховується.
- Калькулятор складає суму застав. Якщо хоча б одна з обраних статей без застави, загальна застава показується як «Немає».
- Ліміт КПЗ задається в корені `laws.json`: `"limits": { "max_jail_minutes": 60 }`. Загальний термін у калькуляторі не перевищує цього значення.
Запис у репозиторій мають лише ті, кому ви дали доступ, тож саме він визначає, хто може змінювати закони.
Не забудьте збільшувати `version` та `updated_at` у `laws.json`.

Якщо репозиторій приватний або ви використовуєте не `raw.githubusercontent.com`, додайте новий домен до `connect-src` у `src-tauri/tauri.conf.json`.

## Як працює оверлей

- Оверлей — це **окреме вікно** без рамки, прозоре й завжди поверх інших. У гру нічого не впроваджується.
- Гаряча клавіша глобальна: спрацьовує, навіть коли фокус у грі. Типова — `F5`. Змінюється в «Налаштуваннях»,
  формат комбінацій: `Ctrl + Space`, `Shift + Tab`, `Alt + G`.
- Вікно можна перетягувати за верхню панель. `Esc` ховає оверлей.
- **Два режими запуску.** Кнопка «Запустити оверлей» питає, як відкрити базу законів:
  **як оверлей** (прозоре вікно без рамки поверх гри) або **як окремий застосунок** (звичайне вікно з рамкою
  в панелі завдань, яке можна згортати й розтягувати). Позначте «Запам’ятати вибір», щоб більше не питати.
  Змінити це можна в «Налаштуваннях» → «Запуск оверлею». Гаряча клавіша відкриває вікно в останньому обраному режимі.
- **Важливо:** оверлей видно лише коли гра працює у **віконному** або **віконному без рамки** режимі.
  Поверх справжнього ексклюзивного повноекранного режиму DirectX жодне стороннє вікно не показується.
- Прозорість і розмір шрифту застосовуються до оверлею одразу.

## Система оновлень

Оновлення поділені на три рівні, щоб гравцям не доводилося щоразу завантажувати застосунок.

| Що змінилося | Як доставляється | Чи потрібен реліз |
|---|---|---|
| Закони, новини, посилання, банер, тема, текст Міранди | Лаунчер сам підтягує зміни з GitHub (`laws.json`, `news.json`, `manifest.json`) | Ні |
| Код застосунку (інтерфейс, нові функції, виправлення) | Вбудований оновлювач Tauri: перевіряє нову версію, завантажує **підписане** оновлення з прогресом, встановлює й перезапускає | Так, але лише тег у Git |
| Критичне оновлення | У `manifest.json` вказуєте `"min_launcher": "1.2.0"`: старіші версії бачать червоне повідомлення про обов’язкове оновлення | Так |

Оновлювач Tauri завантажує **весь інсталятор** (кілька мегабайтів для застосунку на Rust), а не окремі змінені файли.
Таких «дельта-оновлень» Tauri не підтримує, але за цієї ваги пакета це майже непомітно. Найчастіші зміни (закони, новини)
взагалі не потребують нової версії.

### Одноразове налаштування

1. Згенеруйте ключ підпису: `npx tauri signer generate -w olymp.key`. Збережіть файл у безпечному місці.
   **Втрата ключа означає, що вже встановлені копії більше не зможуть оновлюватися.**
2. Публічний ключ із виводу команди вставте в `src-tauri/tauri.conf.json` → `plugins.updater.pubkey`.
3. У тому ж файлі замініть `your-org/olymp-helper` в `endpoints` на свій репозиторій.
   Репозиторій має бути **публічним**, бо оновлювач не авторизується.
4. У GitHub → Settings → Secrets додайте `TAURI_SIGNING_PRIVATE_KEY` (вміст `olymp.key`) і, якщо задавали,
   `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`.

### Випуск оновлення

1. Збільште версію у трьох файлах: `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`.
2. Закомітьте й поставте тег: `git tag v1.2.0 && git push origin v1.2.0`.
3. GitHub Actions (`.github/workflows/release.yml`) збере інсталятор, підпише його, створить реліз і файл `latest.json`.
4. Опис релізу стає текстом повідомлення в лаунчері. Гравці бачать банер «Доступна нова версія» протягом кількох секунд після запуску
   або за кнопкою «Перевірити оновлення» в налаштуваннях.

Локальна збірка (`npm run build`) працює без ключа: підпис потрібен лише для релізів.
Якщо реліз вийшов невдалим, видаліть його на GitHub: `latest.json` знову вкаже на попередню стабільну версію.

## Що нового у версії 1.2.7

- **«Кодекси та Закони»: два незалежні стовпці.** Ліворуч дерево кодексів зі статтями (з пошуком), праворуч повний текст вибраної статті. Кожен стовпець має власну прокрутку,
  а вікно в цьому розділі не прокручується. Під час читання довгої статті список зліва стоїть на місці, не перебудовується й не втрачає позицію. Є кнопка «Копіювати статтю».
- **Додаткові (нестандартні) покарання** в `laws.json`. У статті можна вказати поле `extra` (рядок, кілька значень через `;`, або масив рядків; псевдонім `specialPenalty`):
  ```json
  { "id": "tk-1.2", "number": "1.2", "title": "Керування в стані сп’яніння", "description": "…",
    "fine": 0, "jail_minutes": 0, "wanted_level": 0, "bail": null,
    "extra": "Вилучення водійського посвідчення; Конфіскація транспорту", "tags": ["авто"] }
  ```
  Поле працює і як доповнення до штрафу чи КПЗ, і як єдине покарання (коли штраф і КПЗ дорівнюють 0). У списку статей санкції показуються мітками «Додатково».
  У підсумку калькулятора з’являється блок «Додаткові санкції» з усіма санкціями вибраних статей без повторів. Кнопка «Копіювати підсумок» копіює штраф, КПЗ, розшук, заставу й додаткові санкції одним текстом.
- **Довідник із динамічними розділами.** Розділ задається полем `category` у кожному питанні `faq.json`. Вкладки розділів і заголовки будуються автоматично (порядок першої появи у файлі),
  питання без `category` потрапляють у «Загальне». Розділи поєднуються з пошуком і тегами. Приклад: `docs/examples/faq.json`.
- **Нотатки.** Новий вигляд, кнопки з підтвердженням «✓ Скопійовано!» (також у довіднику, кодексах і підсумку калькулятора), кольорові теги (Важливо, Терміново, Готово, Інфо, Ідеї, Інше):
  можна призначати кілька тегів, у списку вони видні кольоровими точками, зверху є фільтр за кольором.
- **Шаблони нотаток із `templates.json`.** Поруч із «+ Нова нотатка» є кнопка ▾ з випадаючим списком шаблонів. Файл лежить у репозиторії, адреса задається в `manifest.json` → `templates_url`
  (або `DEFAULT_TEMPLATES_URL` у `src/config.js`). Шаблони можна додавати, змінювати й видаляти прямо на GitHub, оновлювати програму не треба: список підхоплюється при запуску й при відкритті вкладки.
  Формат: `{ "templates": [ { "id": "…", "title": "Назва", "text": "Текст з {date} і {time}", "tags": ["red"] } ] }`. У тексті працюють підстановки `{date}` (`{дата}`) та `{time}` (`{час}`),
  а `tags` беруться зі списку `red, amber, green, blue, violet, gray`. Приклад: `docs/examples/templates.json`.

## Що нового у версії 1.2.6

- **Рух і відгук інтерфейсу.** Послідовна поява елементів під час запуску та перемикання вкладок, ковзна акцентна смуга в меню, легке підняття й м’яке сяйво карток і кнопок,
  відгук на натискання (стиснення), «дихання» зеленого індикатора. Матове скло (`backdrop-filter`) застосовано до модальних вікон, сповіщень і міні-панелі оверлею.
  Розмиття гри за вікном оверлею неможливе: вікно прозоре, і браузерний рушій бачить лише власний вміст.
- **Мінімалістичний оверлей.** Тонші лінії, монохромні акценти, акуратніші іконки. Усі елементи керування (наскрізний режим, замок, прозорість, закриття) зібрано в одну міні-панель,
  яка ледь помітна й проявляється при наведенні курсору. Калькулятор, кодекси, довідник і нотатки збережено, лише компактніші.
- **Менеджер гарячих клавіш** («Налаштування» → «Гарячі клавіші»). Дії: показати / сховати оверлей, наскрізний режим (більше не жорстко Shift + F5), замок позиції, вимкнути оверлей,
  пошук по законах. Призначення через «Натисніть клавішу…» (Esc скасовує, Backspace очищає), кнопки «Очистити» й «Скинути», «Скинути всі».
  Клавіші розпізнаються за фізичним кодом, тому розкладка не має значення. Перевіряються дублікати та правила: глобальній клавіші потрібен Ctrl / Alt / Shift або F-клавіша.
- **Профілі налаштувань** («Налаштування» → «Профіль налаштувань»). Кнопка «Експортувати» створює короткий код `OLYP1.…` (тема й власні теми, прозорість, бінди, режими, положення й розмір оверлею, замок),
  який копіюється в буфер. Кнопка «Імпортувати» застосовує чужий код. Код вважається недовіреним: кожне значення перевіряється, а все некоректне відхиляється.
- **Кнопка «Підтримати автора»** замінила «Знайшли баг? / Підтримка». Посилання поки заглушка `#`. Скоригуйте `data-u` у `src/index.html` (кнопка `#donate`), коли буде адреса.
- **Оптимізація.** Відкладений запис повзунків у сховище, `content-visibility` для довгих списків статей, пауза анімацій у прихованому вікні, рідша перевірка новин поза вкладкою «Новини»,
  у Rust: довші паузи фонових потоків без роботи й легший запит процесів.
- **Формат новин v1.2.6** (`docs/examples/news.json`): `id`, `date`, `title`, `tags[]`, `summary` (короткий опис), `content` (детальний текст). Картка показує теги й опис,
  а клік по ній відкриває повний текст. Старий формат (`tag`, `text`) теж читається.

### Версії на кшталт 1.2.5.1 або 1.2.6 Beta

- **Чотирискладовий номер `1.2.5.1` не можна.** Tauri, Cargo і механізм оновлень вимагають формат SemVer `MAJOR.MINOR.PATCH`. Для виправлення просто піднімайте останнє число (`1.2.6` → `1.2.7`).
- **Бета-версію можна** як SemVer-мітку: `1.2.6-beta.1`, `1.2.6-beta.2`, `1.2.6-rc.1`. Вона вважається старішою за `1.2.6`, тож фінальний реліз її замінить. Лаунчер це порівняння вже враховує.
- Бета не повинна потрапляти до всіх гравців. Позначайте такий реліз на GitHub як **Pre-release**: посилання `releases/latest` (яке читає оновлювач і яким користуються гравці) пререлізи ігнорує.
  Окремий канал бета-тестерів потребує власного файлу оновлень (`latest.json` в іншому місці) і не реалізований.
- Версію бети вказуйте в `package.json`, `src-tauri/Cargo.toml` і `tauri.conf.json`, а тег пишіть `v1.2.6-beta.1`.

  Текст і посилання задає `manifest.json` → `banner` (`title`, `text`, `button`, `url`). Посилання підключення: `https://…` або `mtasa://ip:порт`.

  У режимі «окремий застосунок» (з системною рамкою) замок блокує зміну розміру, а перетягування за системну рамку лишається.
- **Поверх усіх вікон, розумна прозорість, наскрізний режим:** перемикачі в «Налаштуваннях» → «Оверлей». У фоні (без фокусу) оверлей стає прозорішим, при наведенні миші повертається повна яскравість.

## Безпека інтерфейсу (з версії 1.2.4)

Застосунок працює на движку браузера, тому його вбудовані функції закрито:
- **Контекстне меню** (правий клік: «Зберегти як…», «Друк», «Переглянути код», «Оновити») вимкнено. Також вимкнено клавішу «меню» та Shift+F10.
- **Гарячі клавіші браузера** заблоковано: усі F1–F12 (зокрема F12 і F5 на сторінці), Ctrl+U/S/P/R/O/N/F/+/−/0, Ctrl+Shift+комбінації, Alt+←/→. Працюють лише Ctrl+C/V/X/A/Z/Y/K, причому за кодом клавіші, тому в українській розкладці теж. Ctrl+колесо (масштаб) не діє.
- **Перетягування:** зображення й текст не перетягуються, а файл, кинутий у вікно, не відкривається як сторінка. Друк вимкнено.
- **Нові вікна й переходи:** `window.open` вимкнено, а навігація на зовнішні сайти й `file://` блокується на рівні застосунку. Зовнішні посилання відкриваються лише через системний браузер і лише за схемою `https://`.
- **Інструменти розробника** у релізній збірці вимкнені (функція `devtools` Tauri не підключена).
- **Політика CSP** суворіша: заборонено вбудовані скрипти, `object`, `frame`, зміна `base` і відправлення форм. Мережеві запити дозволено лише до `raw.githubusercontent.com`.
- Весь текст із файлів адміністрації виводиться з екрануванням (HTML не виконується), а зображення з SVG показуються як картинки без виконання скриптів.
- Команди сховища мають ліміти розміру, а імена процесів гри обрізаються до розумної довжини.
- Нотатки, налаштування та кеші лежать лише у зашифрованих файлах в AppData.

Це зменшує ризики, але не робить застосунок «непробивним»: користувач із відладчиком усе одно може отримати доступ до власного комп’ютера. Захист розрахований на звичайних гравців.

3. плавно відкриває інтерфейс.

Кожен реліз додатково містить файл зі **сталою назвою** `Olymp-Helper-Setup.exe`. Посилання на нього не змінюється між версіями

### Захист локальних файлів
Усі дані застосунку зберігаються тільки в `%APPDATA%\ua.olymp.helper\` у трьох файлах (`settings.oly`, `cache.oly`, `notes.oly`):
налаштування, кеш законів/довідника/маніфесту й нотатки. Звичайні файли `.json` або `localStorage` більше не використовуються.
- **Шифрування:** AES-256-GCM. У Блокноті файл виглядає як випадковий набір байтів.
- **Цілісність:** GCM автентифікує вміст, а ім’я файлу входить в автентифікацію. Будь-яка зміна вручну, пошкодження чи підміна файлу іншим файлом
  виявляється під час запуску.
- **Автовідновлення:** перед кожним записом попередня справна копія зберігається як `.bak`. Якщо основний файл зіпсовано, береться копія.
  Якщо зіпсовано обидва, файл створюється заново: закони, довідник і маніфест завантажуються з сервера, налаштування скидаються до типових.
  Користувач бачить повідомлення про відновлення.
- **Ключ:** SHA-256 від секрету збірки та ідентифікатора комп’ютера. Файли, скопійовані на інший ПК, не розшифровуються.
  Нотатки не переносяться між комп’ютерами та після перевстановлення Windows. Це наслідок прив’язки до ПК.
- **Оверлей** не дублює дані: він бере їх зі спільного сховища, а зміни головного вікна підхоплює автоматично.

**Секрет збірки (потрібно один раз).** Згенеруйте випадковий рядок у PowerShell:
```
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | ForEach-Object {[char]$_})
```
Додайте його в GitHub → Settings → Secrets → Actions як `OLYMP_STORE_SECRET`. Без секрету збірка використовує тестовий ключ, який видно в коді.
Не змінюйте секрет між версіями, інакше всі користувачі одноразово втратять локальні нотатки та налаштування.
Локальна збірка (`npm run build`) без секрету дає застосунок із іншим ключем, ніж у релізі. Якщо ставите його поверх релізної версії,
дані буде відновлено «з нуля».

**Чесне обмеження:** застосунок має розшифровувати свої файли сам, тож рішучий користувач із відладчиком теоретично може дістати ключ.
Цей захист не дає змінювати файли вручну й непомітно, а також виявляє будь-яке втручання, але це не захист рівня банківського сховища.

## Поширені проблеми

- **Гаряча клавіша не спрацьовує:** її вже використовує інша програма. Оберіть іншу комбінацію.
- **Оверлей не видно в грі:** перемкніть гру на віконний режим без рамки.
- **«Гру не запущено»:** перевірте назву процесу в налаштуваннях (наприклад, `GTA5.exe`, `ragemp_v.exe`, `gta_sa.exe`).
- **Помилка збірки на Windows:** переконайтеся, що встановлено Build Tools з компонентом C++.
