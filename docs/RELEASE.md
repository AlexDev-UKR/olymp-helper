# Регламент випуску Olymp Helper

Мета: кожен реліз збирається однаково, інсталятор лишається чистим для антивірусів, а автооновлення завжди працює.

## 1. Підготовка

1. Перевірте зміни локально: `npm run dev`, пройдіться по вкладках, запустіть оверлей.
2. Підніміть версію **в трьох файлах** (формат `X.Y.Z`, для бети `X.Y.Z-beta.N`):
   `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`.
3. Створіть `docs/release-notes/vX.Y.Z.md`. Перший рядок це заголовок, який гравці бачать у вікні оновлення, далі короткий список змін простою мовою.
4. Перевірте версії: `node scripts/check-version.mjs vX.Y.Z` (у CI ця перевірка виконується автоматично).

## 2. Випуск

```
git add .
git commit -m "version X.Y.Z"
git push
git tag vX.Y.Z
git push origin vX.Y.Z
```

GitHub Actions (`.github/workflows/release.yml`):
1. перевіряє збіг версій;
2. збирає фронтенд (легка мінімізація, без агресивної обфускації) і Rust-частину;
3. створює інсталятор NSIS (установка для поточного користувача, без прав адміністратора);
4. підписує пакет оновлення ключем Tauri (`.sig`) і, **якщо задано сертифікат**, підписує `.exe` підписом Authenticode;
5. створює реліз із `latest.json`, версійним інсталятором і `Olymp-Helper-Setup.exe` зі сталою назвою;
6. додає `SHA256SUMS.txt` і перевіряє, що в релізі є всі потрібні файли.

Для тегів із дефісом (`v1.3.0-beta.1`) реліз позначається як Pre-release: посилання `releases/latest` його не бачить, тож звичайні гравці бету не отримають.

## 3. Секрети репозиторію

| Секрет | Призначення | Обов'язковий |
|---|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` і `..._PASSWORD` | підпис оновлень (без нього автооновлення не працює) | так |
| `OLYMP_STORE_SECRET` | ключ шифрування локальних даних (не змінювати між версіями) | так |
| `WINDOWS_CERTIFICATE` (base64 `.pfx`) і `WINDOWS_CERTIFICATE_PASSWORD` | підпис `.exe` сертифікатом Authenticode | ні, але дуже бажаний |

Закодувати сертифікат: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard`.

## 4. Перевірка після випуску

1. У Releases є `latest.json`, `*-setup.exe`, `*-setup.exe.sig`, `Olymp-Helper-Setup.exe`, `SHA256SUMS.txt`.
2. Запустіть попередню версію: має з'явитися «Завантаження версії…» і застосунок має перезапуститися оновленим.
3. Скачайте `Olymp-Helper-Setup.exe` у чистому браузері, перегляньте попередження SmartScreen (див. нижче).
4. Звірте SHA-256 файлу з `SHA256SUMS.txt`.

## 5. Відкат

Якщо реліз невдалий, видаліть його в Releases (або позначте Draft): `latest.json` знову вказуватиме на попередню версію. Тег видаляйте командою `git push origin :refs/tags/vX.Y.Z`. Нову спробу випускайте під новим номером.

## 6. Антивіруси та SmartScreen: що робимо і чого не робимо

Робимо:
- інсталятор NSIS для поточного користувача (не просить прав адміністратора, не пише в системні папки);
- метадані у файлі: видавець, опис, авторські права (`src-tauri/tauri.release.json`);
- JS у застосунку лише мінімізується; агресивна обфускація вмикається вручну (`OLYMP_OBFUSCATION=strong`) і не рекомендується;
- глобальні гарячі клавіші через `RegisterHotKey` (без перехоплювачів клавіатури), перевірка процесу гри лише за назвою;
- публікуємо контрольні суми й даємо сталe посилання на офіційний інсталятор.

Не робимо:
- пакувальники й стискачі виконуваних файлів (UPX тощо);
- самовпаковані архіви та інсталятори-завантажувачі, що завантажують і запускають файли;
- обфускацію або шифрування самого бінарника.

Якщо антивірус усе ж спрацював:
1. Подайте файл як хибне спрацювання: Microsoft (https://www.microsoft.com/wdsi/filesubmission), Kaspersky, ESET, Avast/AVG, Bitdefender (форми на їхніх сайтах).
2. У коментарі вкажіть, що це інсталятор Tauri/NSIS, і додайте посилання на реліз та SHA-256.
3. Підписуйте `.exe`: це найефективніший захід. Без підпису SmartScreen показує «Невідомий видавець» доти, доки файл не набере репутацію.

Варіанти підпису (від простого до надійного):
- OV-сертифікат Authenticode від центру сертифікації (приблизно 100-250 USD на рік): прибирає «Невідомий видавець», репутація зростає з кількістю завантажень;
- EV-сертифікат (дорожчий, на апаратному ключі): репутація практично одразу, але складніший у CI;
- Azure Trusted Signing: недорога підписка, але доступність залежить від країни та типу організації;
- SignPath Foundation: безкоштовно для відкритих проєктів.
